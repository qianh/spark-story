# Spark Story

面向个人创作者的本机 AI 动漫短剧制作工作台。通过阶段看板组织制作，以主控 Agent 协调专业 Agent，支持文字模型通过 CLI 或 API 调用，媒体模型通过 API 接入。

当前制作主线是：先规划整部作品，再跑通**第一集**从剧本到成片的流程。全剧分集规划不代表全部集数已经完成视频制作。

## 快速开始

### 环境准备

- Bun：安装依赖、运行服务和测试；项目使用 `bun:sqlite`，不能直接换成 Node.js 启动。
- FFmpeg 和 ffprobe：媒体探测、关键帧提取、拼接、音频与字幕合成需要在服务进程的 `PATH` 中找到它们。
- 至少一个可用的文字连接：已安装并登录的 CLI，或有权限调用对应模型的 API Key。
- 制作图片、视频和配音时，另需配置对应媒体 API，或导入已有素材。

当前本机流程主要在 macOS 环境验证；CLI 中断使用 POSIX 进程组信号，Windows 原生运行尚未验证。

在项目根目录执行：

```bash
bun install
bun run build
bun run start
```

浏览器打开 **http://127.0.0.1:4310**。服务启动后保持终端运行；关闭网页不会停止后台任务，停止服务则会中断本地执行。

开发模式：

```bash
bun run dev
```

打开 **http://127.0.0.1:5173**。前端通过 Vite 将 `/api` 代理到端口 4310。开发模式会监听后端文件变更，不建议在长时间制作任务运行时修改后端代码。

## 第一次制作怎么操作

1. 打开左侧「模型与连接」，添加连接、检查可用性，并绑定「主模型」和「文本模型」。同一个连接可以承担多个角色。
2. 新建项目，输入一句话创意、大致剧情或剧本素材，选择画风、画幅、API 预算及制作规则。支持 `9:16`、`16:9` 和自定义比例。
3. 在阶段看板点击「进入当前工作区」，或点击对应任务卡，进入 Agent 工作区后点击「开始执行」。进入工作区本身不等于启动生成。
4. 查看实时草稿、任务状态和运行记录。文本生成完成后，主控先审核；通过后才交给你确认。
5. 确认当前产物后，返回看板，进入下一个已就绪阶段并开始执行。不要把「故事概要已确认」误认为「全剧规划或第一集剧本已完成」。
6. 进入媒体阶段前，绑定所需图片、视频、语音等连接；在资产和媒体工作区检查生成结果，必要时导入或替换素材。

刷新页面后，查看当前阶段状态即可。若显示正在生成或审核，不需要重复点击开始；若显示连接待处理，应先查看错误原因，再恢复执行。

连接或额度问题修正后，回到原任务的 Agent 工作区，点击「开始执行」重试，不必重建作品。服务重启后已中断的任务也从原工作区继续；如果存在待确认的干预方案，需要先确认方案，不能用开始按钮绕过。

## 制作流程与确认点

| 阶段         | 主要内容                                                         |
| ------------ | ---------------------------------------------------------------- |
| 故事概要     | 整部故事主线、人物关系、世界规则和阶段走向                       |
| 全剧分集规划 | 先展开情节清单并由主控审核，再按单集容量拆集、生成计时依据并审核 |
| 第一集剧本   | 依据已确认的第一集边界，生成具体场景、动作和对白                 |
| 定妆与资产   | 角色定妆、场景及道具等资产规划与图片                             |
| 分镜预览     | 镜头规划、关键帧和动态分镜预览                                   |
| 正式镜头     | 根据分镜和参考资产生成视频镜头                                   |
| 后期成片     | 配音、音乐及音效、字幕和视频合成                                 |

主控审核未通过时会返工，通常最多追加 3 次；仍不通过则需要人工处理。关键阶段通过主控后仍需你确认，不能绕过确认关卡直接推进下游。

文字草稿支持 Markdown 预览和直接编辑。更改已确认上游会使相关下游失效、等待重新确认；历史产物保留，但不再作为当前有效版本。

### 每集演多少内容

默认目标为 **90～120 秒**。画风模板与叙事模板是不同配置：前者控制视觉风格，后者控制钩子、冲突、转折及收尾等叙事结构。

分集不是先指定 22、60 或 80 集，再均分故事，而是：

1. 展开完整情节单元及因果步骤，保留铺垫、选择、后果与人物反应。
2. 按具体戏剧目标和自然断点分配到各集。
3. 用试写对白、动作、独立反应和转场估算表演时间，检查超载、空余及步骤覆盖。
4. 进行逐集主控审核及整体审核，再交给用户确认。

情节单元数不等于最终集数。一个冲突可以连续演多集，不要求每集完成一个大事件。

当前容量默认值包括：中文每秒 3.5 个发音单元、最多 2 个场景、2 个新角色、1 个新规则、1 个重大变化；独立反应至少占 12%，内容估时保留 10% 余量，无依据空余不超过 25%。这些是可调的制作估算，不是行业统一标准，也不是最终成片时长保证；配音和动态分镜仍需复核。

## 模型与连接

### 角色分工

| 角色     | 用途                                     |
| -------- | ---------------------------------------- |
| 主模型   | 理解要求、审核专业产物、协调干预与返工   |
| 文本模型 | 故事、分集、剧本、分镜等文字与结构化规划 |
| 图片模型 | 定妆、资产和关键帧图片                   |
| 视频模型 | 视频镜头生成                             |
| 语音模型 | 配音                                     |
| 其他     | 音乐、音效等；口型同步使用专用绑定       |

### CLI 接入

已实现 Codex CLI、Claude Code、Grok Build 的非交互调用及结构化输出适配。启动时会尝试发现 `PATH` 中的 `codex`、`claude`、`grok`；也可以手动填写可执行文件的**绝对路径**。

- CLI 应先在本机终端完成安装、登录和权限配置。工作台的探测主要检查可执行文件及版本，不代表账号额度和所有模型能力都已验证。
- 主控与文本角色可以复用 CLI，也可以分别绑定不同连接。
- `grokcli` 有配置入口，但非交互协议尚未验证，当前不能用于实际生成；它与已适配的 Grok Build 不同。
- CLI 当前用于文字及支持范围内的审核，不会自动替代图片、视频或语音 API。

CLI 不受项目 API 金额预算限制，但仍有安全保护：默认连续 **10 分钟无正文更新**时停止，单次调用总时长上限为 **2 小时**。相同正文快照和普通日志不会重置正文活动计时。

连接数据的 `settings.cliIdleTimeoutSeconds` 和 `settings.cliMaxDurationSeconds` 可覆盖这两个默认值，单位为秒，分别接受 1～86400 的有限数值；无效值回退默认值。这是连接数据字段，不代表页面已有专用输入控件。另有正文 4 MB、单条协议消息 8 MB、累计协议流 256 MB 的保护限制。

### API 接入

配置连接时需要提供协议类型、模型 ID、Base URL、密钥环境变量名和每次调用的预留额度。可以在界面保存 API Key，也可以由启动服务的环境提供密钥。

文字调用实际支持 Anthropic Messages 和 OpenAI Chat Completions 兼容协议。Base URL 填 API 前缀，连接器会追加 `/messages` 或 `/chat/completions`，不要把完整接口路径重复填入前缀。

媒体连接器当前实现的协议范围如下；**协议适配不代表每个账号、模型或兼容服务都支持表内所有能力**。

| 协议类型                | 媒体能力                                               |
| ----------------------- | ------------------------------------------------------ |
| `openai` / `compatible` | 图片、视频、语音                                       |
| `xai`                   | 图片、视频                                             |
| `gemini`                | 图片                                                   |
| `elevenlabs`            | 语音、音乐、音效                                       |
| `sync`                  | 口型同步                                               |
| `media-gateway`         | 自定义网关提供的图片、视频、语音、音乐、音效、口型同步 |

`media-gateway` 不是任意供应商接口的自动转换器，需要实现本项目约定的提交与查询协议，见 [media-service.ts](apps/server/media-service.ts)。Gemini 原生文字接口也不能仅凭选择协议名称直接使用，应提供受支持的文字兼容端点。

API 地址必须为 HTTPS，或本机 `localhost` / `127.0.0.1` 的 HTTP 地址。主控进行图片审核时还需要模型及连接器支持视觉输入。

### 预算与中断

- API 调用先预留额度，超出项目预算时暂停。显示金额包含预留、暂估和未知费用，不等同于供应商最终账单。
- CLI 不做 API 金额扣减；遇到供应商限流、额度不足、认证失败或安全上限时仍会停止。
- 子 Agent 的立即中断只停止自己的本地任务；跨任务影响由主控协调。
- 明确的修改要求可进入协调和重做；「不满意」「不够好」等模糊反馈需要先确认具体方案。
- 本地中断不保证已提交到外部供应商的媒体任务被取消。远端提交状态未知时，不应盲目重发，以免重复计费。

## 数据与安全

默认数据目录为项目根目录下的 `.spark-story/`：

| 路径                  | 内容                                       |
| --------------------- | ------------------------------------------ |
| `state.sqlite`        | 项目、任务、修订、产物、事件、预算及检查点 |
| `credentials.json`    | 界面保存的 API Key                         |
| `runs/`               | 各次调用的工作目录和提示词                 |
| `media/`              | 保存的媒体素材                             |
| `frames/`、`renders/` | 提取帧与合成中间文件                       |

可通过 `SPARK_DATA_DIR` 指定数据目录，通过 `PORT` 指定后端端口。请始终从项目根目录启动；若修改开发模式后端端口，还需同步 Vite 的代理配置。

密钥文件使用 `0600` 权限，但内容是**本机明文存储，并非加密保险库**。不要将数据目录、密钥、原始素材或包含提示词的运行目录提交到代码仓库、公开分享或上传日志平台。

备份时，先等待任务停止并关闭服务，再复制整个数据目录；不要在 SQLite 写入期间只复制 `state.sqlite` 而遗漏 WAL。恢复应在服务停止状态下进行，保留原目录副本，并避免覆盖新产生的数据。服务重启会将未完成的本地执行转为可处理的中断状态，不会悄悄继续旧进程。

具体操作：在工作区确认没有仍在生成或审核的本地任务，然后在启动服务的终端按 `Ctrl+C`，等待进程退出，再用文件管理器复制整个 `.spark-story` 目录到独立备份位置。该目录是隐藏目录，需打开文件管理器的隐藏文件显示。外部媒体任务是否结束仍需单独核实。

工作台默认仅监听 `127.0.0.1`，没有面向公网的多用户认证体系。不要直接暴露到公网。

## 常见问题

### 一直在等待，怎么判断是否运行？

进入当前 Agent 工作区查看生成/审核状态、最近输出和运行记录。后台心跳只表示服务还活着，不等于模型正在输出。文字草稿会增量显示，但完整结构化数据仍需生成结束后才能校验与确认。

### 看到「CLI 执行超过 15 分钟」怎么办？

这是旧版固定超时策略留下的错误。当前版本使用上述空闲与总时长保护。更新代码后需重启服务才生效；重启前先处理正在运行的任务。失败记录不会因更新代码自动变成成功。

同一任务修订下，失败草稿中的完整、可解析情节清单可以恢复为候选，仍须主控审核；截断或存在多份冲突清单时不会自动恢复。不要为重试随意修改制作规则，否则会产生新修订，不能直接复用旧修订的恢复条件。

恢复不是保证从最后一个字接着生成：完整情节清单和已保存的检查点可复用，未完成的普通文本调用可能需要重新生成。

### 外部媒体生成中断了，要重新生成吗？

在媒体工作区找到原任务。有远端任务 ID 时，使用「继续查询」获取原任务结果，不要新建重复任务。提交状态未知且没有远端 ID 时，先在供应商侧核实是否接单或计费；只有确认可以再次提交后，才使用「已核实，允许重试」。

### 为什么文字能生成，图片或视频却失败？

仅绑定主模型和文本 CLI 不够。检查对应媒体角色是否绑定 API、密钥是否存在、模型是否支持该能力、预算是否充足，以及 FFmpeg/ffprobe 是否可用。协议兼容性或供应商权限错误需要针对具体响应处理。

### 可以直接输入完整长篇小说吗？

项目输入支持小说/剧本类别，但当前不是无限长文档处理系统：创建接口允许最多 120000 字符，实际执行对来源超过 30000 字符会拦截。尚未实现完整的长篇分块导入与检索流程；请先准备保留关键人物、因果与结局的素材摘要。

### 能一次自动做完所有集吗？

当前全剧规划可包含多集，整个七阶段主线中，全剧规划之后的制作阶段聚焦第一集闭环。不要把全剧规划、媒体适配器或测试通过理解为所有集数自动批量成片、或所有供应商均已实机验证。

## 开发与验证

```bash
bun run typecheck
bun test tests --coverage
bun run build
bunx playwright install chromium
bunx playwright test
```

端到端测试使用端口 4311 和独立的临时项目数据目录，不使用当前作品数据库。媒体集成测试需要 FFmpeg；外部模型多数使用本地测试替身，不能替代真实账号的供应商兼容性验证。

主要代码入口：

- [apps/web/](apps/web/)：阶段看板、Agent 工作区、Markdown 与媒体预览。
- [apps/server/index.ts](apps/server/index.ts)：本机 HTTP 服务和接口。
- [apps/server/runtime.ts](apps/server/runtime.ts)：任务执行、审核与干预。
- [apps/server/story-planner.ts](apps/server/story-planner.ts)：情节清单、检查点与恢复。
- [apps/server/connectors.ts](apps/server/connectors.ts)：文字 API / CLI 适配。
- [apps/server/media-pipeline.ts](apps/server/media-pipeline.ts)：媒体阶段编排。
- [apps/server/media-service.ts](apps/server/media-service.ts)、[media-files.ts](apps/server/media-files.ts)：媒体供应商任务和本地处理。
- [packages/](packages/)：领域结构、生产规则及容量校验。
- [tests/](tests/)、[e2e/](e2e/)：单元、集成及浏览器测试。
