# Spark Story 实施与验收

版本：0.1；日期：2026-09-05。

依据：[产品设计](01-产品设计.md)、[技术设计](02-技术设计.md)。当前仅完成设计；本文件是后续开发拆分，不表示功能已实现。

## 1. 开发顺序

先建立可持久运行的任务与资产骨架，再纵向跑通内容到成片，然后补齐供应商适配和复杂干预场景。各阶段是开发顺序，不缩减最终已确认范围；不能用只支持一家供应商的演示宣称全部完成。

| 阶段 | 开发内容 | 可检查交付 | 依赖 |
| --- | --- | --- | --- |
| M0 接入验证 | 本机工具能力探测、CLI 协议样本、API 能力矩阵、媒体工具检查 | 可复核的探测报告和适配测试样本 | 无 |
| M1 持久底座 | 本机服务、SQLite、任务/尝试/事件、文件库、租约、SSE、配置 | 重启后可还原的任务看板 | M0 |
| M2 主控协作 | Agent 定义、输入快照、派发、交付校验、审核、返工、干预 | 主控与两个专业任务真实交接 | M1 |
| M3 故事到预览 | 三类入口、故事库、剧本、资产、声音、分镜、动态预览 | 可审核的第一集动态分镜 | M2 |
| M4 预览到成片 | 正式关键帧、视频、音画路线、音乐音效、字幕、混音、导出 | 一集真实制作的可播放成片 | M3 |
| M5 操作与恢复完善 | 局部编辑、版本选择、依赖重做、崩溃恢复、费用结算 | 完整工作区与故障场景验证 | M2–M4 |
| M6 多供应商验收 | 补齐明确 CLI、API 接入范围，验证切换和能力差异 | 每个连接的支持状态与真实验收证据 | M0–M5 |

不在设计阶段给出缺乏账号和生成耗时依据的工期、单集价格或质量保证。开发工作量、模型生成时间和人工审阅时间分别记录。

## 2. 可执行工作包

### M0：先解决接入事实

- T001：探测 bun、FFmpeg/ffprobe、各 CLI 路径和版本；不自动升级或安装用户工具。
- T002：Codex、Claude Code、Grok Build 分别验证启动、文本事件、结构化交付、中断、恢复、退出码和权限等待。
- T003：识别用户所指 grokcli 的实际发行项目；若尚未安装，先完成发行包和协议核实，再按后续实施授权安装联调。
- T004：给每类模型配置能力表；验证 API 与 CLI 不会因命令名相同被混为一个连接。
- T005：制定供应商能力探针。区分离线帮助探测、只读账号检查与可能付费的最小生成；禁止后台隐藏付费探测。

### M1：底座

- T101：数据迁移、外键、唯一约束、任务状态与乐观锁。
- T102：任务队列、租约、心跳、Outbox 与事件补发。
- T103：不可变媒体库、hash、临时文件发布、元数据提取、Range 播放。
- T104：本机服务启动和关闭网页后继续运行；退出后台与重启恢复区分。
- T105：连接配置、密钥引用、项目覆盖、API 预算预留与 CLI 可用性。

### M2：Agent 编排

- T201：预设 Agent 定义及版本管理；职责、工具和模型可编辑。
- T202：主控命令契约、专业交付 Schema、任务上下文装配。
- T203：实际产物检查、主控审核、首次生成加 3 轮质量返工。
- T204：阶段审核 manifest、用户明确意见与模糊否定分流。
- T205：中断屏障、子 Agent 自身停止、主控跨任务协调、迟到结果处理。
- T206：CLI 工具网关和任务作用域权限；验证工作目录隔离的实际强度。

### M3：内容与预览

- T301：三类输入、长文分段解析、来源锚点、覆盖率。
- T302：故事概要、人物事实、世界规则、适度改编说明与审核。
- T303：第一集分场剧本、稳定对白 ID、版本差异编辑。
- T304：多套视觉模板、角色/场景/道具资产、正式版本与引用。
- T305：声音推荐、统一台词试听、角色声音绑定。
- T306：分镜结构、逻辑镜头与生成片段、动态分镜合成及审核。

### M4：正式生产与后期

- T401：图片生成与参考资产绑定，关键帧候选及主控审核。
- T402：视频异步提交、轮询、取消、下载、原生音画与独立音轨路线。
- T403：正式配音、台词对齐、口型处理与音轨重复检测。
- T404：AI 音乐/音效及本地导入，分轨放置、对白期间压低音乐。
- T405：结构化时间线、字幕、标准化、自动拼接与导出。
- T406：成片主控检查、用户审片与定点修改。

### M5–M6：完整体验与联调

- T501：阶段看板、主控聊天、专业工作区、产物对比与实时干预。
- T502：局部编辑、正式版本切换、精确依赖失效和重做。
- T503：提交不确定性恢复、费用未知状态、磁盘空间与备份。
- T504：六类模型覆盖、供应商备用顺序、运行间切换、跨供应商声音与参考图能力检查。
- T505：对所有指定 CLI 和列入首版交付的 API 适配建立真实样本；未通过的标记待验证并列为未完成项。

## 3. 核心验收场景

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 一句话输入 | 可生成整体概要，经确认后细化第一集，不强制预设集数 |
| A02 | 粗略剧情 | 原始内容保留，补全内容和改编可以识别、修改 |
| A03 | 长篇小说/剧本 | 展示解析覆盖，人物事实可追溯，不把未读章节声称为已梳理 |
| A04 | 六类配置 | 修改项目模型不改变已运行任务的配置快照；新任务用新绑定 |
| A05 | 主控与子 Agent | 专业产物交回主控，未通过不能进入用户正式审核包 |
| A06 | 返工 | 首次失败后最多额外 3 次，达到上限暂停；限流不消耗质量轮次 |
| A07 | 关键审核关卡 | 动态分镜未批准前，不提交正式视频任务 |
| A08 | 明确干预 | 用户要求改银发后，目标 Agent 立即停自己，主控协调并直接继续 |
| A09 | 模糊干预 | 用户只说“不够好”时，生成方案等待确认，不擅自重做 |
| A10 | 子 Agent 权限 | 子 Agent 调用停止其他任务接口被拒绝 |
| A11 | 中断迟到结果 | 旧视频返回时保留但不覆盖新版本、不解除新任务的审核关卡 |
| A12 | 主控暂不可用 | 中断汇报不丢失，影响分支不晋升，无关任务可继续 |
| A13 | API 并发预算 | 两个任务争用不足以覆盖两者的余额时，最多允许一个成功预留 |
| A14 | CLI 预算例外 | API 预算耗尽后，独立 CLI 文本任务仍能继续；其付费媒体 API 被拦截 |
| A15 | CLI 不可用 | 限流等待、额度耗尽暂停或按明确重置时间恢复，不无限快速重试 |
| A16 | 外部提交丢响应 | 先核验幂等键/job，不重复提交；不能核实则明确显示状态未知 |
| A17 | 网页关闭/刷新 | 后台继续，事件序号恢复后界面状态无重复或漏失 |
| A18 | 后台崩溃 | 恢复任务、外部 job 和文件，不重复扣费，旧 lease 写入失败 |
| A19 | 正式版本选择 | 新候选不覆盖正式版；批准旧审核页面不意外批准新候选 |
| A20 | 局部修改 | 仅改音乐时不重生成视频；改台词时更新配音、字幕和必要口型 |
| A21 | 音画路线 | 不支持原生音画的模型不被分配该路线；已确认角色声音保持约束 |
| A22 | 动态分镜 | 可播放临时配音与图像草稿，能看出节奏并回到具体镜头修改 |
| A23 | 成片 | 实际图片、视频、音频完成合成，字幕可读，无丢片、双对白和损坏文件 |
| A24 | 导出 | 成片、字幕、分轨与清单可打开，引用版本与批准时间线一致 |
| A25 | 可切换执行器 | 同一 Agent 任务能用不同已通过联调的连接交付同种结构化产物 |
| A26 | 画幅 | 9:16、16:9 可跑通；自定义比例不支持时明确适配，不能静默拉伸 |

A01–A03 可用不同输入验证前半段，共享同一真实第一集成片验证后半段；不要求为了入口数量生成三部剧。

## 4. 验证策略

确定性核心使用自动测试：状态转换、作用域权限、并发预算、修订屏障、幂等提交、依赖失效和事件去重。适配器使用脱敏事件样本做协议测试，覆盖半行 JSON、断流、未知事件、取消失败与非零退出。

媒体用小型测试素材验证解码、时间基准、字幕、音轨归属和合成缓存。浏览器端覆盖创建项目、阶段审批、任务干预、版本切换和局部编辑主路径。

模型创作质量使用真实产物和用户审阅验证，不能靠模拟响应证明。真实 API 测试遵循预算；没有账号或额度时报告具体缺项，不能以 mock 测试替代供应商已接入结论。

故障注入至少覆盖：外部请求成功后断网、数据库提交前后崩溃、CLI 中断不响应、旧进程返回、磁盘写满、下载 URL 失效、后台重启、同时点击两次批准。

## 5. 设计阶段已核实与尚未核实

已核实：项目目录开始为空；存在本机 Codex、Claude Code、Grok 命令；它们的帮助输出有非交互相关能力；已核对部分供应商官方资料。具体版本与来源在技术设计中记录。

尚未核实：各 CLI 登录和可用额度、grokcli 具体发行包、API Key 与账号权限、真实图像/视频/声音质量、供应商费用、取消幂等能力、机器媒体处理性能。以上作为实施探针与联调项，不阻止当前产品和技术设计完成。
